## Purpose

This file maps the programming languages used or targeted in the public portfolio.

The public wording focuses on data systems, numerical computing, simulation, model validation, automation, infrastructure, systems programming, time-series analytics and platform engineering.

---

## Core language positioning

| Language | Public positioning | Portfolio use |
|---|---|---|
| Python | Primary language for data, ML, MLOps, APIs and automation | Data pipelines, MLflow, FastAPI, Streamlit, tests, scripts |
| SQL | Core language for data systems and quality controls | PostgreSQL, Oracle-style checks, reconciliation, data migration |
| Bash / Shell | Linux operations and automation | runbooks, cron, service checks, deployment scripts |
| JSON | Configuration, API payloads and structured evidence | API examples, model metadata, data contracts |
| HTML / CSS | Web foundations and documentation interfaces | portfolio pages, dashboards, web-development evidence |
| JavaScript | Web interaction and lightweight tooling | dashboards, UI prototypes, Node.js utilities if needed |
| C / C++ | Systems, performance and numerical engines | performance-critical components, simulation kernels, platform extensions |
| Rust | Safe systems programming and high-reliability tooling | future CLI tools, validators, data-processing utilities |
| Go | Concurrent services and infrastructure tooling | future data services, internal APIs, monitoring agents |
| R | Statistics, analytics and reporting | statistical validation, exploratory analysis, actuarial-style analytics |
| Julia | Numerical computing and scientific simulation | optimization, simulation, quantitative models, high-performance notebooks |
| MATLAB | Scientific computing and numerical prototyping | numerical methods, signal processing, simulation prototypes |
| Specialized platform scripting | Domain-specific automation and time-series prototyping | platform-specific prototypes, simulation interfaces, structured automation |

## Public portfolio rule

Languages are included as technical capability signals. They should be backed by public evidence over time:

- Python: active repos and tests;
- SQL: DataOps and migration repos;
- Bash: infra runbooks and automation;
- HTML/CSS/JavaScript: web portfolio and dashboards;
- R/Julia/MATLAB: statistical/numerical notebooks or scripts;
- C/C++/Rust/Go: small utilities, validators or performance-oriented prototypes;
- specialized platform scripting: documented carefully and never used as the central public identity.
