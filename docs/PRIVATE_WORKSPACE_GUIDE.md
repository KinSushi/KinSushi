# Private Workspace Guide

This file documents what should exist outside public GitHub.

It is a boundary guide, not application material. Do not add the actual private files to this repository.

---

## Recommended private folder structure

```text
career_private/
├── cv/
│   ├── cv_dataops_fr.pdf
│   ├── cv_mlops_en.pdf
│   ├── cv_data_engineer_fr.pdf
│   └── cv_application_support_fr.pdf
├── cover_letters/
├── job_tracker.xlsx
├── interview_prep/
├── company_notes/
├── recruiter_messages/
├── salary_strategy/
├── certificates_private/
├── school_documents/
└── work_permit_documents/
```

---

## Why this stays private

| Material | Reason |
|---|---|
| CV variants | Employer-specific and personal |
| Cover letters | Application material |
| Job tracker | Private search strategy |
| Recruiter messages | Private communication |
| Salary strategy | Negotiation material |
| School documents | Administrative/private |
| Certificates with IDs | Personal identifiers |
| Work-permit documents | Identity/legal material |

---

## What public GitHub should receive instead

| Private artifact | Public equivalent |
|---|---|
| CV claim | Technical repo evidence |
| Interview story | Runbook / post-mortem / README section |
| Certification PDF | Public certification mapping without IDs |
| Company-specific note | Employer-neutral technical positioning |
| Salary target | No public equivalent |

---

## Rule

If a file helps apply to a specific company, keep it private.

If a file proves technical skill without exposing personal or employer-specific material, it can be public.
